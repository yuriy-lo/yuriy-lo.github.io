Do you remember eXtreme Programming? It was trendy in 2001, when I started my university studies. Now Google Trends shows that people forgot it. But in reality most of XP's practices are now software industry's best practices:

* Planning game is widely used even though different implementations exist.
* Small releases are frequently desired.
* Simple design is something that every developer wants.
* Metaphor concept is similar to Ubiquitous language from DDD.
* Test driven development is the must now days.
* Refactoring is what developers do all the time.
* Pair programming was replaced by code reviews.
* Collective ownership of code is a default approach.
* Continuous integration is also the must.
* 40-hour week is a way to achieve good productivity on a long run.
* On-site customer role is played by Product owners and domain experts.
* Coding standards compliance is checked automatically.

10 out of 12 practices are now something that development teams are expected to use every day and a lot of software is available to make that practices easy to do. Metaphor was difficult concept from the very beginning; I have seen it in action and I was impressed. Only pair programming  is not there in its original meaning (single developer is not allowed to contribute to product code and tests). Instead, code review practice was adopted from open source world.
